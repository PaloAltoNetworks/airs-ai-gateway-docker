# Architecture

## Stack

- **Bash** — single script, `set -euo pipefail`, shebang `#!/usr/bin/env bash`. Bash 3.2 compatible
  (macOS ships 3.2, so no associative arrays).
- **curl** — health probes and egress checks. HTTPS-only (`--proto =https`).
- **awk** — the `values.yaml` reader, with `yq` used instead when present (ADR-004).
- **Docker** + **Docker Compose** (v1 or v2) — runs the stack from a generated, hardened compose file.

`curl` is the only hard startup dependency (checked by `require_basics`). Docker is checked by
per-mode preflight.

## Single-file layout

The whole tool is `setup-panw-ai-gateway.sh`. Internal organization is by function prefix:

| Group | Names | Role |
|---|---|---|
| Modes | `do_install`, `do_from_values`, `do_status`, `do_validate`, `do_diagnose` | One per CLI mode; dispatched at the bottom |
| Values ingestion | `values_get`, `values_get_awk`, `values_env_keys` | Read the SCM `values.yaml` |
| Generation | `write_runtime_env`, `write_compose`, `detect_health_client` | Emit `.env.runtime` and `docker-compose.yml` |
| Config | `load_env`, `env_quote`, `emit_env` | Read/write `.env`, safely |
| Helpers | `die`, `info`/`warn`/`error`, `http_probe`, `log_deploy`, `version_ge`, `validate_uuid` | Cross-cutting |

## The chart is the spec

The installer reproduces, by hand, what `helm template` would render. Three pieces of the upstream
chart matter and are mirrored in constants at the top of the script:

| Chart source | Installer constant | What it carries |
|---|---|---|
| `airsgateway.builtinDefaults` | `CHART_ENV_DEFAULTS` | `ALBUS_BASEPATH`, `CONTROL_PLANE_BASEPATH`, `LOG_STORE`, `ANALYTICS_STORE` |
| `values.yaml` `environment.data` | `CHART_ENV_DEFAULTS` | `SERVICE_NAME`, `PORT`, `MCP_PORT`, `SERVER_MODE`, `LOG_STORE_FILE_PATH_FORMAT` |
| `airsgateway.redisEnv` + `redis/secrets.yaml` | `write_runtime_env` | `REDIS_URL`, `CACHE_STORE`, `REDIS_TLS_ENABLED`, `REDIS_MODE` |

None of these appear in the customer's downloaded `values.yaml`. Helm supplies them by deep-merging
underneath `environment.data`, so `do_from_values` lays the defaults down first and lets the
customer file override. See ADR-006 — this is the part most likely to rot when the chart moves.

The `*_KEYS` arrays (`CACHE_STORE_KEYS`, `LOG_STORE_KEYS`) mirror the chart's `cacheStore.commonEnv`
and `logStore.commonEnv` helpers: they are the allowlist of variables passed through to the
container.

## Generated artifacts

| File | Generated by | Committed? |
|---|---|---|
| `.env` | `--from-values` | No (gitignored) |
| `.env.runtime` | install | No (gitignored) |
| `docker-compose.yml` | install | No (gitignored) |
| `deploy.log` | every install/pull | No (gitignored) |
| `.image-digest` | install | No (gitignored) |

`.env` is the operator's source of truth. `.env.runtime` holds only what the container needs, so
setup-only material (registry password) never enters the container's environment.

## Container hardening

The generated compose file mirrors the chart's `securityContext` and `podSecurityContext`:

```yaml
user: "1000:1000"                      # runAsNonRoot + runAsUser/runAsGroup 1000
read_only: true                        # readOnlyRootFilesystem
tmpfs: [/tmp]                          # the chart's emptyDir at /tmp
security_opt: [no-new-privileges:true] # allowPrivilegeEscalation: false
cap_drop: [ALL]                        # capabilities.drop: ALL
```

Plus Compose-side limits the chart leaves to the cluster: `mem_limit`, `cpus`, `pids_limit`,
`restart: unless-stopped`, and json-file log rotation. The gateway image is pinned by digest after
pull, so `compose up` cannot pick up a mutated tag.

Redis gets the same treatment minus the read-only rootfs (it writes its own dataset) and is not
published to the host — only the gateway reaches it, over the Compose network.

## Redis topology

Bundled by default, matching the chart. When the operator sets `CACHE_STORE` to a managed backend
(or points `REDIS_URL` off-box), `uses_external_redis` returns true and the Redis service plus the
`depends_on` block are omitted entirely — the compose file then describes one container.

## Security model

- Secret files written under `umask 077`, then `chmod 600`.
- `.env` values are single-quoted with `'\''` escaping, so a credential containing backticks or
  `$()` cannot execute on source (ADR-007). Covered by a regression test.
- The registry password reaches `docker login` via `--password-stdin`, never argv, so it is
  invisible in `ps`.
- Credential-handling paths disable shell tracing (`set +x`).
- `--dry-run` redacts everything in `SECRET_KEYS` before printing.
- `deploy.log` records image digests and timestamps, never secrets.
- Keys read from `values.yaml` are validated against `^[A-Za-z_][A-Za-z0-9_]*$` before export, so a
  malformed file cannot inject `PATH` or `LD_PRELOAD`.

## CI / release

- Lint workflow: ShellCheck + shfmt (2-space) on push and PR.
- Release workflow on tag push: attaches the `.sh` plus a Sigstore build-provenance attestation,
  body is changelog-only.
- All GitHub Actions SHA-pinned (org rule).
